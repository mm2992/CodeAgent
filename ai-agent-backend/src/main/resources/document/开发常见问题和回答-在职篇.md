#### 问题 1：Spring Boot 项目启动慢，如何快速定位并优化？

**答**：  
启动慢通常源于：  
- **自动配置加载过多**：通过 `--debug` 启动，查看自动配置报告，排除不需要的配置类（`@EnableAutoConfiguration` 中 exclude）。  
- **数据源初始化连接池耗时**：调整 `spring.datasource.hikari.connection-timeout` 和 `maximum-pool-size`，或改为懒加载。  
- **类扫描路径过广**：指定 `@SpringBootApplication(scanBasePackages)` 缩小扫描范围。  
建议使用 Actuator 的 `/actuator/startup` 端点分析启动耗时阶段。

#### 问题 2：MySQL 中一条 SQL 执行很慢，Explain 后看到 Using filesort，怎么解决？

**答**：  
`Using filesort` 表示排序无法利用索引，需要额外排序操作。解决方法：  
- 检查 `ORDER BY` 字段是否与查询条件中的索引顺序一致（最左前缀原则）。  
- 为排序字段创建联合索引，例如 `WHERE a=1 ORDER BY b`，可建索引 `(a,b)`。  
- 若数据量巨大，考虑分页限制或使用覆盖索引（`SELECT` 只查索引字段）。  
- 调整 `sort_buffer_size` 大小，但治标不治本，优先优化索引。

#### 问题 3：服务间调用（Feign/Dubbo）频繁超时，如何排查？

**答**：  
分三步：  
1. **确认是客户端超时还是服务端处理慢**：查看服务端日志响应时间，若服务端快则可能是网络或网关限流。  
2. **检查线程池耗尽**：服务端业务线程池若排队严重，需调大核心线程数或使用异步非阻塞。  
3. **调整超时配置**：Feign 可设置 `connectTimeout` 和 `readTimeout`，同时设置重试机制（注意幂等性）。  
建议增加全链路 Trace ID，配合日志链路分析具体环节。

#### 问题 4：Redis 缓存穿透/击穿/雪崩如何区分与应对？

**答**：  
- **穿透**：查询不存在的数据，绕过缓存直达 DB。应对：布隆过滤器 + 缓存空值（TTL 短）。  
- **击穿**：热点 key 过期，高并发同时查 DB。应对：互斥锁（SETNX）或逻辑过期（不设置 TTL，后台异步更新）。  
- **雪崩**：大量 key 同一时间过期或 Redis 宕机。应对：过期时间加随机偏移量，以及多级缓存+限流降级。  
实际生产常组合使用，并监控缓存命中率。

#### 问题 5：Jenkins 构建时总报“OutOfMemoryError: PermGen space”（JDK 8 以前），怎么解决？

**答**：  
对于 JDK 8 及以下，持久代（PermGen）空间不足。处理：  
- 在 Jenkins 的 `jenkins.xml` 或启动脚本中添加 JVM 参数：`-XX:MaxPermSize=512m`（JDK 8 后改为 `-XX:MaxMetaspaceSize=512m`）。  
- 若使用 Maven/Gradle，可分别配置 `MAVEN_OPTS` 或 `GRADLE_OPTS` 增加元空间。  
- 检查是否有内存泄漏（如频繁加载动态类），升级到 JDK 11+ 可避免 PermGen 概念。

#### 问题 6：接口返回的数据顺序混乱，明明用了 `LinkedHashMap` 还是乱序？

**答**：  
原因可能是序列化（如 Jackson）时默认使用 `HashMap` 导致无序。解决方案：  
- 在实体类上使用 `@JsonSerialize(as = LinkedHashMap.class)` 或指定 `@JsonPropertyOrder`。  
- 若返回 `Map` 类型，确保声明为 `LinkedHashMap` 而非 `HashMap`。  
- 或者使用 `TreeMap` 按自然排序，但需确认业务是否需要特定顺序。  
建议统一封装响应对象，并用 `List` 或明确的 DTO 字段替代自由 Map。
